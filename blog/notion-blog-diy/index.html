文組小白花兩個晚上，用notion架出部落格系統

2026.09.23 ・ by Rosy ・ 閱讀約 3 分鐘

在Claude的幫忙下，我串接了notion成為我的部落格發文器。

為什麼我沒選 WordPress

身邊大部分自己架站的人都是選用WordPress，本來我也想說乾脆一頭跳進WordPress的世界好了，但是在跟AI討論過數次之後，這件事對現在的我來說，學習成本跟維護成本都有點高，也因此在年初的時候想說用vibe coding架一個簡易網站就當交差了。

而在最近接觸越來越多vibe coding跟各種工具的串接可能性之後，｢自己架一個部落格系統吧」這樣的想法開始從我腦中跑出來。

原本設想是做一個線上編輯器，然後文章發布成網頁連接到原有網站。 但在跟AI來回討論過幾次，考量到原本的使用習慣，再加上我時間零碎，需要跨裝置隨時隨地編輯，最好還可以跟我原有的app或是草稿們做連結，少一點搬運的力氣，與重新發想的時間。

選擇用Notion 當編輯器

「那如果是用Notion 當我的編輯器呢？」

前期在Google Docs 跟Notion 中間其實掙扎許久。

Notion最後勝出的是在他的資料庫系統，比起Google Docs一篇一篇的儲存看起來有條理的多，除了可以讓所有的文章列表呈現得更清楚之外，還可以一眼看出什麼是草稿什麼是已發佈的文章，甚至還可以排程（但我大概用不到）再加上有欄位的設置，讓大P人如我可以有個依靠的去思考關於SEO的配置。

再來，也是很重要的，就是我大部分有紀錄的草稿都還是存留在notion裡。

於是就這樣開始了建構之旅。

文組小白的架站之旅

慶幸自己在今年三、四月架網站的時候，就像是參與了一次先修班，從Claude到GitHub的串聯走過一次，對串接API也有一些經驗。

因此這一次將想要的功能確定好之後，後面基本上就是按照AI給的步驟，一步一步地透過程式碼跟Notion 的 API Key 串接，做出一個work flow。

讓我用兩個吃完晚餐後的夜晚，一邊陪女兒火車快飛，一邊用筆電把這個小系統做出來。 或許未來會寫一篇教學文，或許不會（由衷的覺得自己還不夠格）但就是想用第一篇文章記錄一個文組、社科院的小白，在現代科技的幫助下，用極低的成本建置了一個靠近理想中的網站系統。

「窮酸感」反而是一人創業的底氣

有的時候會覺得在小公司待久了，會有一種窮酸感。在有限的金錢、與資源下，怎麼樣能夠以一己之力做出最大的產出。但也是這種先天不足的限制感，讓我摸出很多極簡…嗯，或許不是極簡，但應該是極低成本的先行方案，有的時候甚至你要我花錢我還不知道怎麼花（笑）。

不過也因為如此，在一人創業的路上走起來雖然辛苦但也不痛苦，因為當你看見自己蓋出來的房子之後，會有種「其實我也可以嘛！」的爽快。
